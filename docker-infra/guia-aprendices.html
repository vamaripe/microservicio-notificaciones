Guía para levantar la base de datos por ambiente

Infraestructura: Docker + PostgreSQL + Liquibase Julio 2026
Antes de comenzar — reglas obligatorias
  • Nunca escribas CREATE DATABASE en ningún changelog ni script SQL. El contenedor crea la base de datos automáticamente.
  • Solo debes aplicar los changelogs de Liquibase correspondientes a tu módulo asignado.
  • No modifiques los archivos Dockerfile, docker-compose.yml ni los .env.*.

Prerrequisitos

Docker Desktop instalado y corriendo
Git instalado
Repositorio de tu módulo clonado
Carpeta docker-infra recibida del instructor

Estructura de carpetas esperada

carpeta-de-trabajo/ ├── docker-infra/ ← carpeta que te entrega el instructor │ ├── Dockerfile │ ├── docker-compose.yml │ ├── .env.develop │ ├── .env.qa │ ├── .env.staging │ └── .env.main │ └── design-software-<tu-modulo>-db/ ← tu repo clonado aquí, al mismo nivel └── changelog-master.yaml

Comandos por ambiente

Todos los comandos se ejecutan desde dentro de la carpeta docker-infra/.

develop design-software-develop
1
Entrar a la carpeta
$ cd docker-infra
2
Levantar PostgreSQL Crea el contenedor y la base de datos design-software-develop.
$ docker compose --env-file .env.develop up postgres -d
3
Aplicar los changelogs de tu módulo Reemplaza <modulo> con el nombre de tu módulo (ver tabla abajo).
$ docker compose --env-file .env.develop --profile tooling run --rm liquibase-<modulo> update

¿Qué hace Liquibase y cómo agregar estructura?

Flujo de trabajo con Liquibase
1
Primera ejecución Liquibase crea automáticamente dos tablas de control en la base de datos: DATABASECHANGELOG (registro de cada changeset aplicado) y DATABASECHANGELOGLOCK (bloqueo para evitar ejecuciones paralelas). Nunca las toques manualmente.
2
Agregar nueva estructura Crea un nuevo archivo SQL o YAML dentro de la carpeta correspondiente de tu repo (ej. 01_ddl/03_tables/) y referéncialo en el changelog-master.yaml. Cada changeset debe tener un id único y tu nombre de autor.
3
Volver a correr update Liquibase compara lo que ya está aplicado contra tu changelog. Solo ejecuta los changesets nuevos — los anteriores no se repiten. Esto es lo que permite ir agregando estructura de forma incremental y segura.
4
Bajar el contenedor al terminar
$ docker compose --env-file .env.develop down # Agrega -v solo si quieres borrar también los datos del volumen
¿Cómo verificar que la base de datos quedó bien?
  • Conéctate con cualquier cliente SQL (DBeaver, DataGrip, pgAdmin) a localhost:5432.
  • Usa las credenciales del archivo .env del ambiente que levantaste.
  • Debes ver la base de datos design-software-<ambiente> y las tablas DATABASECHANGELOG y DATABASECHANGELOGLOCK si Liquibase ya corrió.
